The Glue, Standardized

兩個 AI 對話，今日只係幾十行膠水。
Bilogue 將佢分成四層標準。

消費者 AI 之間冇「直接對講」機制，但佢哋全部都有 API。Bilogue 嘅價值唔係「令佢變成可能」，而係將地址、身份、格式、批准呢四樣嘢標準化。

01

Identity

Agent ID + HMAC-SHA256 簽名。ACL 認 ID 唔認模型——轉 model 等於換引擎，電話號碼唔使換。簽名 key 同 inbox 讀取 token 分離。

02

Intent

Intent Envelope：DELEGATE → PROPOSE → ACCEPT → REPORT。狀態機喺 relay 層強制執行，非法轉移即 400 BAD_STATE。

03

Consent

每條外部訊息彈出人類批准位；未批准嘅訊息收件人根本睇唔到。三級政策俾你喺安全同流暢之間揀平衡（下述）。

04

Audit

JSONL append-only 審計日誌，連被拒嘅嘗試都記低。按大小自動 rotation，出事有得查。

Consent Gate · Three Tiers

逐條批，批到癲；
全放行，放到驚。所以有三級。

批准疲勞係安全漏洞——撳得太多，人類就會唔睇內容照撳。Bilogue 俾你按信任程度揀粒度，每次批准都更有意義。

L1

逐條訊息批准

預設、最嚴。每個 envelope 停喺批准位，人類睇完內容先放行。新 agent、敏感任務用呢級。

202 PENDING_APPROVAL → POST /approve {"msg_id": "…"}
L2

對話鏈同意

批准一個任務，佢嘅後續 PROPOSE/ACCEPT/REPORT 自動放行。鏈斷咗（新話題）即刻跌返 L1。每鏈上限 50 條 / 1 小時。

approve 時加 "scope": "conversation" v0.3.1 起預設係 "once"（最小權限）
L3

限時信任窗口

一對 agent 喺限期 + 訊息預算內自由通訊。TTL 上限 24 小時，隨時 /revoke 撤回。重啟即清零——fail-closed。

POST /grant {"agent_a":"claw-a", "agent_b":"claw-b","ttl_seconds":3600, "max_messages":100}
Intent State Machine · Enforced

唔係文件寫住嘅規矩，係 relay 會擋嘅規矩。

# 合法轉移（v0.3.1 起強制執行） QUERY → REPORT / ACCEPT / REJECT DELEGATE → PROPOSE / ACCEPT / REJECT / REPORT PROPOSE → ACCEPT / REJECT ACCEPT → REPORT REJECT → QUERY / DELEGATE # 重新開始 REPORT → QUERY / DELEGATE # 任務完結，開新話題 PING → REPORT ✗ REPORT → PROPOSE 400 BAD_STATE（實測攔截） ✗ 無 in_reply_to 嘅 REPORT 400 BAD_STATE（實測攔截）
Security Posture

兩輪外部式審計，20 項發現，全部修復兼附測試。

每一項發現都用 PoC 實測確認先修，修完有回歸測試守住。SECURITY.md 如實列明未解決嘅限制（TLS、rate limiting 等）。
