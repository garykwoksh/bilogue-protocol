## 一、v0.3 保安複審結果

上輪（v0.2.1）修咗 SEC-01~14，今輪集中審 v0.3 新增嘅 Consent 三級政策代碼（`/grant`、`/revoke`、`/grants`、L2 對話鏈）同埋成個 attack surface 再過一次。

### 1.1 新發現（v0.3 引入或之前遺留，未修）

| ID | 嚴重度 | 問題 | 說明 | 建議修法 |
|---|---|---|---|---|
| SEC-15 | 中 | **`conversations` 無清理機制** | 每次 `approve(scope=conversation)` 新增一條，永遠唔删；而且 `_check_conversation` 每條 `/send` 都遍歷全部 conversations → 合法流量都可以造成記憶體 + CPU 雙重消耗（O(n) 放大） | 加 TTL（例如 1 小時）+ 總量上限，惰性清理（同 `_expire_pending` 同款） |
| SEC-16 | 中 | **Slow-loris 式線程耗盡** | v0.2.1 換咗 `ThreadingHTTPServer`，但線程數無上限，`rfile.read(content_length)` 冇 timeout——攻擊者開大量連線慢慢餵 body，可以耗盡線程 | socket 層加 request timeout；前置 reverse proxy（Caddy/Nginx）做連線限制（正路部署本來就應該有 proxy 做 TLS） |
| SEC-17 | 低 | **`approve` 預設 `scope=conversation` 係「默默擴大授權」** | Admin 以為只係放一條訊息，其實預設開咗成條對話鏈（50 條）。違反最小權限原則 | 預設改做 `scope=once`，要開鏈就明確寫 `conversation`（breaking change，要喺 release note 講清楚） |
| SEC-18 | 低 | **`pair_grants` 無上限** | 雖然 `/grant` 係 admin-only，但冇總數上限，admin token 洩漏後攻擊者可以建立大量 grant 做掩護 | 加上限（例如 1000）+ audit log 已有記錄，配合告警 |
| SEC-19 | 低 | **Audit log 無 rotation** | `relay_inbox.jsonl` 單檔無限增長，長期運行會填滿磁碟 | 部署文件寫明用 logrotate；或代碼層按大小切檔 |
| SEC-20 | 資訊 | **Intent 狀態機未強制執行** | README/SPEC 定義咗 DELEGATE→PROPOSE→ACCEPT→REPORT 嘅合法轉移，但 relay 只檢查 intent_type 合唔合法，唔檢查狀態轉移（例如未 DELEGATE 就直接 REPORT） | v0.4 喺 relay 層加狀態機驗證（per conversation） |

### 1.2 已知限制（SECURITY.md 已列，重新確認仍然成立）

- 冇 TLS（要 reverse proxy）、冇 rate limiting、單 relay 架構、JSONL 非防篡改、nonce cache 重啟清零、kill-switch 狀態唔持久、grant 狀態唔持久（fail-closed）

### 1.3 複審結論

v0.3 嘅核心授權邏輯（grant 檢查次序：簽名 → nonce → ACL → L3 → L2 → L1）係正確嘅——**grant 唔會繞過簽名/ACL，只繞過 Consent Gate**，呢個係設計本意。需要修嘅係上面 6 項，全部已喺 **v0.3.1 修復**（2026-09-26 完成，57/57 回歸測試通過），M1 唔使再排呢項。

## 五、Landing page：要唔要？

**要，但係唔使使錢。** 理由：

- AI agent 協定呢個賽道而家有 A2A（Google）、ANP、AGNTCY（Cisco）等對手，人哋全部有像樣嘅項目頁；一個光脱脱嘅 repo 會令「Consent Gate 係差異化賣點」呢個故事講唔出去
- GitHub Pages 免費、同 repo 同一個工作流程，`docs/` 或者獨立 branch 一放就上線

**建議**：M2 用 GitHub Pages + 手寫單頁 HTML（項目本身就有 `index.html` 架構可視化嘅底子）。Carrd（$19/年）只喺你唔想郁代碼時先考慮。

**頁面內容大綱**（單頁）：

1. Hero：一句話定位 ——「AI-to-AI 通信協定，每條外部訊息都有人类批准位」+ 兩個掣（GitHub / Quickstart）
2. 15 秒 demo GIF（`--demo` 模式嘅終端輸出，或者架構圖動畫）
3. 三級 Consent 政策圖解（L1→L2→L3，呢個係最新嘅差異化功能）
4. 同 A2A/MCP 嘅關係圖（互補而唔係對抗）
5. 安全姿態（SEC-01~14 已修 + OSTIF 審計申請中）
6. Quickstart 代碼塊（複製即用）
7. Roadmap 摘要 + 點樣參與
